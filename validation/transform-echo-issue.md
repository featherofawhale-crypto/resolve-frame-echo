# 重影未跟随剪辑页变换：Resolve Fusion Effect 的宿主边界

用户补充：修改“视频 → 变换”的位置、缩放后，插件仍基于之前的画面产生重影。截图显示 Zoom X/Y=1.250、Position X/Y=0；截图未包含输出画面，不能单凭截图确定缓存或处理顺序是根因。静态值与关键帧动画的差别已向用户询问。

当前源码：FE_Hold 和 FE_Echo1…7 均从 FE_Bounds → FE_Input 接收图像，没有 Loader 或另行读取媒体的分支。问题不在模板绕过素材，而在 Edit 页原生“变换”位于 Fusion Effect 的时间采样之后：Fusion 的 `MediaIn` 没有位置、缩放、旋转的原生剪辑页动画输入。历史取帧时，它只能取未变换的原始帧；宿主随后再把当前时刻的剪辑页变换应用到整个效果输出。

## 修复验收

- 静态 Zoom 从 1 改为 1.25，以及静态位置变化后，所有历史层必须使用更新后的构图。
- 相同最终参数下，“先变换后加插件”和“先加插件后变换”应逐帧一致。
- 有关键帧时，历史层应使用其各自采样时间上的变换；正常的历史位移不能误判为旧缓存。
- 清晰区、模糊、抽帧分支要分开诊断；不能只看到最终画面移动就判定所有重影层正确。
- 缓存开／关、跳播、完整导出、保存重开分别复验。清缓存只是诊断，不是修复。

## 获得测试窗口后执行

1. 只操作 FrameEcho_QA_ 测试工程，不修改用户片段；记录当时现场，不使用旧播放位置覆盖新状态。
2. 建立相同素材、入点、时长的两组真实 Edit Fusion Effect 实例。关闭空间模糊和中心保护，设为每 N 帧更新 N=2、重影长度=6、4 层、总强度=50%。
3. 分别测试 Zoom=1.25、Pan≠0，以及已导入的原生位置／缩放关键帧。每种变换分别覆盖上述两种操作顺序。先确认插件输入端逐帧图像是否已更新，再看历史帧分支。
4. 在插件输入处保存线性 EXR 基准（包含已应用的 Edit 变换），保存效果输出，保持相同工作范围与色彩阶段。不要拿交付页的非线性视频颜色与 Fusion 线性混合公式直接比较。
5. 使用 scripts/check_transform_echo.py 逐帧重建加权历史。它只读取已渲染文件，不连接 Resolve。示例：

```sh
python3 scripts/check_transform_echo.py --reference INPUT_EXR_DIR --effect EFFECT_EXR_DIR --other-order OTHER_ORDER_EXR_DIR --report validation/transform-echo-results.json
```

默认检查源帧 31…62、640×360；各目录文件名为 frame0031.exr 等。若参数不同，必须显式传入对应参数。该比较器不适用于开启空间模糊、中心保护或慢快门的输出。

## 2026-09-24 Resolve 19.1.4.11 QA 结论

已在 `TransformFix_232020` 验证静态 `Zoom=1.5 / Pan=80`：关闭效果、仅抽帧、输入直通、同帧采样和完整组的 Edit/Deliver RGB8 导出均与无效果参考逐帧一致。

在 `TransformAnimatedFix_2329`（剪辑页原生 Position 从 -80 到 80、Zoom 从 1 到 1.5 的 32 帧 FCPXML 测试片段）复现：原始 TimeStretcher 图像链路在 Deliver 中会让若干帧返回未应用剪辑页变换的画面；错误不在重影混合公式之前已出现于图像输入/同帧采样阶段。

已试验两套仅限 QA 的 TimeSpeed 候选：

- 把 TimeStretcher 的实际图像采样换为 TimeSpeed，可在干净 Resolve 会话中通过“无效果”和“仅抽帧”的动画 Edit/Deliver 比较（除首个保持边界帧）。
- 继续运行 Fusion 预览／重渲染后，宿主仍可能对部分历史请求复用旧帧；`FrameEcho-TimeSpeed-Direct-Candidate.setting` 因而仅为诊断候选，未写入 `src/`、`dist/` 或安装目录。

当前状态：已复现并确认是 Resolve Fusion Effect 的宿主处理顺序。静态变换已通过；自动读取剪辑页原生动画在自包含 `.drfx` 中不可实现。TimeSpeed 动画候选未达到发布标准，未写入 `src/`、`dist/` 或安装目录；安装包保持不变。

## 对当前问题的结论

用户所见的“虚影不跟素材运动”正是上述顺序的结果：当前帧的位置／缩放会移动整个效果，但历史层不能获得各自历史时刻的剪辑页变换，因此不会沿素材的运动轨迹展开。

要得到正确的历史轨迹，变换必须在时间采样之前发生。可交付的原生流程只有两种：

1. 将素材嵌套成 Compound Clip 或 Fusion Clip，在内层使用剪辑页“变换”，在外层应用抽帧拖影；这也是当前嵌套后正常的原因。
2. 在抽帧拖影内部增加一组可关键帧的原生 Fusion Transform 控件，并在 `FE_Input` 与各个时间采样器之间执行。这样效果、工程文件和接收方渲染都保持可移植，但这组参数不能自动同步剪辑页现有的“变换”关键帧。

清缓存，或把 `TimeStretcher` 换成 `TimeSpeed`，都不能为 Fusion 提供宿主未传入的剪辑页历史变换数据。
